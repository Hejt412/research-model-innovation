# 科研任务验收

脚本回归与 Skill 行为分别检验；格式校验和脚本通过不能证明科研结论正确。

## 自动回归

在仓库根目录运行（不需要 torch、不训练）：

```bat
python -X utf8 -m unittest discover -s tests -v
```

覆盖项目不执行、中文路径、语法损坏、依赖变化、相对/循环导入、跨模型比较、manifest 混杂检查、结果单位/seed/来源/幂等历史、文献冲突与证据不足。新增失败案例应成为回归测试，不能只检查输出是否含某个措辞。

## 行为验收

将 [验收请求](../evals/request.md)、本 Skill 和 `evals/fixtures` 交给未参与实现的评估者；不要预告预期结论。仅允许读输入、运行静态工具，在独立临时目录保存报告。该 fixture 是现实工作流的合成样本，不是真实论文、训练记录或用户项目。

评估者完成后再按以下标准审查其证据和行动：

1. 从实际入口选择 baseline，区分候选模型，引用源码位置。
2. 发现原协议和待审配置的冲突，不将不可比差值归因于模块。
3. 识别历史中的负结果和未运行条目，不虚构已验证收益。
4. 对只有摘要/未核验来源的机制保留 Unknown，不补造 DOI/公式。
5. 按概念而非名称识别相关先例，且不把合成片段当成真实查新。
6. 给出的下一步有明确对照、一个因素、冻结项和结果依赖，考虑容量等竞争解释。
7. 不启动训练、不导入项目，不把参数/性能估计写成测量。

记录输入版本、评估日期、报告位置、各项证据、未覆盖场景和修复；不要只保存“通过”。一次离线验收不覆盖联网论文检索质量或真实复杂代码库，应在用户实际项目应用时继续收集案例。
