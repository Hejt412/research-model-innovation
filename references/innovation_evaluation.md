# 机制迁移与重复风险

对每个机制验证：原问题 → 抽象数学问题 → 当前问题；观测变量是否存在、监督/数据量/模态是否兼容、推理时所需信息是否可得、额外计算是否可接受。相似的“domain shift”措辞不足以证明假设一致。

区分原论文公式与本项目新提案，注明前者的章节/公式编号。给出新变量的形状、作用位置、初始化和禁用后如何还原 baseline。condition 必须注明来自输入、support set 还是已知工况，不能无意依赖测试标签或不可用元数据。SSM 修改需核对连续/离散参数化、离散化、状态稳定性和具体库版本，不能简单把任意矩阵加法当作正确可用实现。

为每个候选建立同领域比较：`P-ID | 原理/数学 | 作用位置 | backbone | 任务 | 数据/划分 | 标签假设 | few-shot/DA/DG | loss/训练 | 核心重合 | 实质差异`。差异应是可检验的机制/假设差异，不只是研究对象或新名称。

| 重复风险 | 使用条件 |
|---|---|
| Green | 已执行并记录合理范围的同领域检索，暂未发现高度相似机制；只对本次范围有效 |
| Yellow | 有类似原理，但存在有证据支持的实质机制差异 |
| Orange | 已有接近实现，潜在差异有限，需缩小创新主张 |
| Red | 相同或高度相似机制已在相近设定应用，不能作为主要新颖性主张 |
| Unknown | 未检索、覆盖不足或关键方法不可访问，无法可靠判定 |

评级需附最接近论文、证据、差异和置信度；低置信度不能包装成 Green。Green 不等于世界首创，更不是法律上的专利新颖性意见。

可用 L0 直接组合、L1 针对性改造、L2 跨领域机制重设计、L3 新问题建模/机制描述研究类型；这不是论文质量、可发表性或新颖性的自动评分。

候选注明主要改变属于模型结构、损失/目标、训练策略、数据处理或超参数。默认先筛选有证据支持、迁移条件成立且可检验的候选，再优先选择结构候选，并综合查新证据、重复风险、实现成本和运行开销排序。结构候选须描述具体的表示构建、交互/融合、连接、路由或状态更新变化；单纯堆叠现成模块、扩容或换 backbone 不自动获得优先级。

优先结构创新不降低证据要求，也不越过协议错误。没有合格结构候选时给出结构方向的补证计划；可把更有依据的非结构方案列为备选并说明原因。用户明确指定其他方向时按其要求排序。收益一律为待检验假设，给出失败模式和竞争解释，不为了完成模板虚构一个“最佳创新”。
