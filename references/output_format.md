# 报告与持久记录

使用 [报告模板](../assets/research_report_template.md)，采用用户语言。完整报告顺序：项目理解、模型结构、Gap Map、跨领域论文、迁移机制、同领域先例、新颖性风险、候选比较、选定单项、改造结构、公式、代码位置/接口、单变量实验、风险与待验证项。

每项代码主张给路径/行号，每项关键文献主张给直接来源与页/节/式号。区分已验证事实、推断、假设、待验证；不适用章节写原因，不用空白营造已完成。若用户只要求部分任务，则缩减而不补做未经请求的训练或实现。

报告使用 G-ID（缺口）、P-ID（论文）、I-ID（创新）、E-ID（实验）、H-ID（历史条目）关联证据。机制卡详见 [创新卡模板](../assets/innovation_card_template.md)，检索和比较表详见 [文献表模板](../assets/literature_table_template.md)。

仅在真实项目内创建/更新 `research_profile.yaml` 和 `research_history.md`，必要时使用项目约定的研究子目录，报告给出路径。用户仅要内联回答时不强制落盘。不要写入 Skill 安装目录或跨项目共享历史。

档案记录证据来源与确认状态；不把模板默认值视为用户项目设置。新历史条目包含日期、baseline commit/config、G/I/E-ID、机制指纹、状态（proposed/implemented/evaluated/rejected）、证据路径/用户提供来源、逐 seed 结果、限制和下一步。evaluated 必须有实际结果证据；失败/否决不删除。用机制指纹而非名称识别重复：作用位置 + 变换 + 数据依赖 + 目标函数。结论变化追加修订记录，不覆盖原始观测。
