# 报告与持久记录

先用一个短决策段说明：推荐结构及其相对 baseline/最接近先例的实质变化、目前最大的未知或阻断项、下一步最小诊断/实现/用户实验。若没有合格候选，直接给原因与补证路径，不虚构推荐。

按用户请求裁剪主体：
- 架构局部分析：代码定位、数据流/轴、缺口与待核实项。
- 创新设计：适用的证据链、候选比较、一个因素的结构/公式/接口和实验；不展开未执行的统计或结果复核。
- 用户核验/结果复核：先说明哪些声明检查通过/失败、来源和覆盖限制，再给必要诊断和历史修订。
- 完整研究：使用 [报告模板](../assets/research_report_template.md) 展开项目、Gap Map、文献/迁移/先例、选定结构、公式/代码和实验。摘要不替代应有证据，局部请求不强制填写14章。

代码主张给路径/行号，关键文献主张给直接来源与页/节/式。区分事实、推断、假设、待验证；不适用或未执行内容明确原因。图或公式必须帮助解释实际信息流，不为填充篇幅添加。

使用 G-ID/P-ID/I-ID/E-ID/H-ID 关联缺口、论文、创新、实验、历史。沿用 [创新卡](../assets/innovation_card_template.md) 和 [文献表](../assets/literature_table_template.md)，局部请求无需先填写所有字段。

档案/历史仅保存在实际项目；使用已有研究子目录，用户仅要内联回答时不强制落盘。不得写入 Skill 安装目录或跨项目共享历史。档案空值不是项目事实。

历史按日期追加，包含 baseline commit/config、证据 ID、机制指纹、状态 proposed/implemented/evaluated/rejected、用户来源、逐 seed 结果、限制和下一步；evaluated 必须有实际结果，失败不删。机制指纹用作用位置+变换+数据依赖+目标函数识别重名/异名重复。结论变更追加修订，只有新证据或协议变化才重提已否决机制；统计与旧记录规范按需加载。
