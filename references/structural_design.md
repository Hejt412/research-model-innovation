# 结构方案、资源约束与用户核验

在候选具备问题和迁移证据后完成本表。源码阅读能确认的设计条件与用户运行才能确认的行为分别记录，不把完整表格当成通过实验。

| 核对项 | 应记录的内容 | 无法满足时 |
|---|---|---|
| 修改位置与原/新计算 | 文件/类/函数、替换的运算、信息路径或状态关系、与已有模块的实质差异 | 保留假设，不靠新名字宣称创新 |
| 完整预测函数 | 从各路输入/表示沿全部 forward、融合、归一化、head 到实际预测量，核对可吸收性、可分离性与联合依赖；列 head/参数约束 | 局部非线性或跨路连接不能代替端到端结论 |
| 输入输出与轴 | 每个入口/分支的形状、batch/channel/token 等轴语义、变长与边界输入 | 未核实形状标记待核验 |
| 连接与残差 | 投影、拼接、广播、残差维度和归一化；必要接口变化是否引入第二因素 | 维度冲突阻止直接实现 |
| 信息可用性 | 条件来自输入/support/状态还是标签，训练与推理分别能获得什么 | 所需信息不可得时拒绝当前方案 |
| 状态与执行约束 | 因果/非因果设定、mask、padding、跨样本状态清理、共享参数、dtype/device | 不符合任务假设时缩小或改写方案 |
| 底层接口 | 已阅读的依赖版本与接口，是否需要改 kernel、缓存或自定义算子 | 未提供的 API 不写成可直接调用 |
| 禁用与初始化 | 关闭机制如何恢复 baseline、公共参数如何匹配、初始化及随机状态控制 | 未核验的等价性只作为设计目标 |
| 初始化可学习性 | 新参数到实际 loss 的依赖、可训练/优化器覆盖、初始化处的导数及阻断来源 | 确定阻断时先修订；不能用形状正确或分支执行代替 |
| 成本与项目预算 | 参数增量、峰值显存、推理延迟、实现复杂度，以及来源和测量条件 | 超过明确预算时降级；成本未知不能当作满足预算 |

## 完整预测函数审查

结构候选深入前，写出 baseline 与候选的完整计算：输入/分支表示 → 新机制 → 后续投影、拼接、归一化、残差、head → 任务实际预测量。不能在新模块的输出处停止。逐项说明三个不同问题：某个参数化能否被已有可训练层吸收；预测是否仍可写成各路独立函数的和（或任务对应的可分解形式）；是否引入了 baseline 缺少的端到端联合依赖。模块执行、局部非线性、新参数与局部跨路连边都不足以回答后两个问题。

结论绑定实际 head 的函数与约束，包括线性/非线性、可训练/fixed/frozen、参数共享、秩/稀疏/正交约束和作用位置。`frozen` 不等于不能把梯度传到 head 的输入。对分类先审查 logits，再区分 softmax/决策后处理；softmax 概率出现非线性差异不能作为 logits 已有交互的证据。回归、重建、分割、预测序列、状态更新等任务审查相应真实输出及后处理，不强行寻找 logits；必要时分别记录结构输出与最终任务量的依赖。

两个常见反例（列向量约定，a,b∈R^d，U∈R^(d×r)，V∈R^(r×d)，W_a,W_b∈R^(k×d)）：

- **纯线性交叉**：a′=a+L_ab b，b′=b+L_ba a，若后续仅有 z=W_a a′+W_b b′+c，则 z=(W_a+W_b L_ba)a+(W_b+W_a L_ab)b+c。对每个这样的候选参数值，原来独立且无约束的可训练线性 head 可以取这两个有效权重，表示同一预测函数；这不证明更强的联合依赖。证明的是该设定下的吸收关系，完整函数族是否相等还要核对 baseline 恢复路径、映射的可逆性等条件。固定/frozen head、共享或其他受约束权重不一定允许有效权重，须核对具体约束；即使无法吸收，以上函数仍是两路加和，不能因此宣称有乘性交互。
- **CrossValue 的局部非线性**：a′=a+U tanh(Vb)，b′=b+U tanh(Va)。同一线性 head 给出 z=[W_a a+W_b U tanh(Va)]+[W_b b+W_a U tanh(Vb)]+c=f(a)+g(b)+c。它可以增加各路的非线性表达能力，通常不能被纯线性 baseline head 吸收，但 logits 仍可分离；共享 U/V、双向命名或 tanh 都不会改变这一结论。若后面还有联合非线性 head、全局归一化或其他运算，需把它们代入完整函数再判断。baseline 的 concat 后若已有联合非线性 head，也可能已经具备联合依赖，不能只读 concat 就宣布缺口。

**CrossGate 的条件性交互**：例如 a′=a⊙[1+α sigmoid(Qb)]，b′=b⊙[1+α sigmoid(Qa)]，Q∈R^(d×d)，α 为标量。线性 head 下新增项 α{W_a[a⊙sigmoid(Qb)]+W_b[b⊙sigmoid(Qa)]}一般允许乘性的两路依赖，但 α=0、门控恒定、下游权重消去该项或数据退化时不一定表现出交互。可学习 α=0 是合法 baseline 等价初始化，不能写成初始已观测交互，也不能因初始输出相同否定设计；初始化学习路径另按下节审查。能表示交互、实际学得交互、改善任务指标与论文新颖性是四个独立结论。

上述是可复用的条件推导，不是万能的矩阵/模块名称判定规则。对 attention、归一化、共享状态、非加和输出或复杂非线性，沿实际计算缩小结论，无法证明就保留未知；不为此添加通用自动数学证明器。

需要区分联合依赖时，可交由用户运行最小四点诊断：在固定参数、mode、RNG 及状态条件下，对语义允许的 (a_1,b_1)、(a_1,b_2)、(a_2,b_1)、(a_2,b_2) 计算 D=F(a_1,b_1)−F(a_1,b_2)−F(a_2,b_1)+F(a_2,b_2)。若 F=f(a)+g(b)，D 恒为零；有限精度下须报告尺度与容差。四点须遵循一致的任务/标签定义且组合合法，不要求四点同类别，允许标签随联合输入合法改变。在该范围内观察到非零 D，支持该固定函数/局部样本存在非加和依赖；越出数据分布的任意特征拼接不直接说明任务机制。一次或有限次零差不能证明全函数可分离，也不能排除其他位置/样本的交互。分类用 logits 做该结构诊断，另报概率变化，不把 softmax 引入的非线性归因于融合；其他任务选真实预测量并解释其可分解假设。代码静态推导、未运行诊断与用户观测分别保存，不在 Codex 执行 forward。

## 初始化处的学习路径

先静态追踪每组新增参数 → 中间量 → 实际 logits/预测 → 训练 loss。读取真实训练调用和优化器参数范围；仅在 forward 中出现，或声明 requires_grad，并不证明参数参与当前 loss 的更新。区分：路径被 detach/no_grad/离散选择截断；参数 frozen 或未被优化器覆盖；固定零门控/相乘因子使局部导数恒零；ReLU 死区、硬阈值或有限精度下饱和造成当前初始化无信号。未提供训练入口、输入分布或数值条件时标为待核实，不能把所有非线性一概判死，也不能把 frozen 公共层误判为其输入一定不可求导。

零门控须区分固定常量与可学习参数：Δh=αf(h) 中，固定 α=0 截断 f 的更新；可学习 α=0 且 f 非零时，α 本身仍可能获得 ⟨g,f(h)⟩ 的梯度，其中 g 是残差相加后的 loss 梯度。前向残差为零不是整个分支不可学的充分条件。

对关键初始化写出局部导数或链式依赖，分别判断“整个新增分支无法开始学习”和“部分参数先为零梯度、其他参数可先更新后打开路径”。例如无偏置残差 Δh=UVh，h∈R^d、V∈R^(r×d)、U∈R^(d×r)，令 g=∂L/∂(h+Δh)，则 ∂L/∂U=g(Vh)^T，∂L/∂V=(U^Tg)h^T。U=V=0 虽使初始输出等于 baseline，但两因子的梯度都恒零；在仅按该 loss 梯度更新、无外部扰动的常规优化设定下无法自行开启。若 U=0、V 用合适尺度的非零初始化，仍有 Δh=0，U 在 Vh 和下游 loss 信号非退化时可先获得梯度，V 首步梯度为零并不等于整个分支被阻断。对调两者亦可，但须按实际形状和下游路径核对，不承诺所有样本都有非零梯度。

提出保持接口、loss、训练/数据协议的最小修订；比较已有实现与修订时把初始化作为唯一变化，不同时加 bias、改 rank、学习率或另加 loss。首次实现结构时，正确初始化是该结构的明确组成部分；不能拿已知无法学习的实现作“公平对照”以制造结构收益。安全初始化、非零梯度或路径连通都只支持可学习性条件，不证明有效优化、机制因果或任务收益。

需要用户实测时，另交独立的梯度诊断脚本/配置和 cmd.exe 命令，列出实际模型/loss 入口、受控非退化输入、参数与初始化摘要、各组 grad 是否为 None/有限/零及观测条件；不调用 optimizer.step、不修改训练协议。记录实际 mode/RNG/状态条件并保持梯度跟踪，不能套用 forward 核验的 inference_mode/no_grad。该入口由用户运行，不能放进 [仅 forward 的结构核验](structure_probe.md) 适配器、spec 或通过判定，也不为补证由 Codex 执行模型/backward。用户返回诊断后结合采样和 loss 解释零/非零；训练效果仍须独立实验。

## 项目预算

可在 [项目档案](../assets/research_profile_template.yaml) 的 resource_budget 填写上限。null 表示用户尚未指定；不自动赋予通用阈值。参数增量 fraction=(新参数量−baseline 参数量)/baseline 参数量，须说明是否包含 frozen/shared 参数及 baseline 配置。显存单位 MiB，延迟单位 ms，并列出硬件、输入形状、batch、dtype、软件版本与测量方式。实现复杂度使用项目约定，例如允许修改的层级/依赖，不制造精确分数。

分别记录用户上限、源码/公式估计、用户实测和当前未知项。估计绑定具体维度、bias、共享/独立实例及 frozen 计数口径；参数化改变后重新计算，不能沿用来源材料的旧百分比。估计超过明确上限可淘汰或在授权范围内提出独立的缩减新方案；估计低于上限只能暂时保留，不能报告实测合格。没有预算时仍报告成本未知，不阻止所有探索。资源补偿导致 lr、训练预算等同时变化时重新设计对照。

## 机制观测与消融

每个深入候选把一个具体结构假设连到可观测量、位置、采集条件、预期趋势、否定条件和一个相关对照。例：路由假设可观察逐条件权重及误差分组，用固定/均匀路由检验输入依赖是否必要；跨分支交互可用独立分支或中性交互作对照。这些只是可选形式，必须适合实际机制，不能据权重分布直接证明因果。

先选择最能区分竞争解释的最小观测；说明与最终指标的关系。观察到预测行为但性能无改善，或容量匹配的普通模块同样改善时缩小主张。中性版本须说明是否改变参数/计算或数据假设；与 E0/E1 分别定义唯一因素。不为记录中间量同时更改 loss 或训练策略，诊断和实验均由用户运行。

## 用户运行的结构核验

实现或用户核验请求按 [核验契约](structure_probe.md) 交付适配模块、spec 和 cmd 命令。用户执行真实 forward；Codex 可读取导出的 JSON 离线复核，不导入项目。报告保存实际导出值、摘要、源码前后快照和 baseline/实验关联，检查形状/有限数、禁用一致性及已声明的机制/状态关系。

只选择任务确需的检查：分支执行、受控门控观测、批次隔离、缓存重置、因果前缀或全长/分块一致性。合法零初始化不要求启用后输出不同；跨样本交互/非因果模型不套不适用性质。未声明或未运行即未核验，声明检查通过也不认证 setup、真实执行或收益。
